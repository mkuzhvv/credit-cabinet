# Запуск приложения и подключение локальной модели

Основной запуск использует четыре контейнера: PostgreSQL, Python-скоринг, Java и Nginx/React. Помощник остаётся включённым и обращается через Spring AI к **нативной Ollama на компьютере**.

Модель не требуется для старта кабинета и рассмотрения заявки. Если Ollama не запущена, чат сообщает о недоступности; загрузка каталога, заполнение и отправка формы продолжают работать.

## 1. Требования

- Docker с Compose V2, запущенный daemon и Linux-контейнеры.
- Для помощника — нативная [Ollama](https://ollama.com/download) и модель `qwen3.5:9b-q4_K_M`.
- Интернет при первой сборке, установке Ollama и скачивании весов.
- Свободное место и память для Qwen 9B и её контекста 12 288 токенов, если используется помощник.

Java, Node.js и Python для контейнерных компонентов устанавливать на хост не нужно. Обязательный `.env` не используется.

## 2. Установка и запуск Ollama

Установить Ollama для [Windows](https://ollama.com/download/windows), [macOS](https://ollama.com/download/mac) или [Linux](https://ollama.com/download/linux). После установки открыть новый терминал и проверить `ollama --version`.

Проверенный нативный runtime — **Ollama 0.40.11**: [официальный релиз и установочные файлы](https://github.com/ollama/ollama/releases/tag/v0.40.11). Загрузка с основной страницы может устанавливать более новую версию; её совместимость нужно проверять отдельно. Модель и её параметры закреплены в Java, digest проверяется перед генерацией.

Официальные инструкции: [Windows](https://docs.ollama.com/windows), [macOS](https://docs.ollama.com/macos), [Linux](https://docs.ollama.com/linux), [переменные окружения](https://docs.ollama.com/faq). Минимальная ОС нативного приложения: Windows 10 22H2 или macOS 14; Apple M поддерживает GPU, Intel Mac — CPU.

### Windows

Завершить ранее запущенную Ollama через значок в трее, если она уже занимает порт. В отдельном PowerShell:

```powershell
$env:OLLAMA_HOST = '127.0.0.1:11434'
ollama serve
```

Терминал остаётся открытым. Этот параметр применяется только к запущенному процессу. Для фонового приложения Windows тот же OLLAMA_HOST задаётся в пользовательских переменных окружения, затем Ollama перезапускается.

### macOS

Для установленного приложения Ollama:

```bash
launchctl setenv OLLAMA_HOST "0.0.0.0:11434"
```

После этого полностью завершить и заново открыть приложение Ollama. На Apple Silicon нативная версия может использовать GPU через Metal.

### Linux

Для ручного запуска, если другой экземпляр Ollama не занимает порт:

```bash
OLLAMA_HOST=0.0.0.0:11434 ollama serve
```

Если Ollama уже работает как systemd-сервис, добавить `Environment="OLLAMA_HOST=0.0.0.0:11434"` в секцию `[Service]` через `sudo systemctl edit ollama.service`, затем выполнить `sudo systemctl daemon-reload` и `sudo systemctl restart ollama`.

В проверенном Docker Desktop на Windows контейнер подключается через host.docker.internal к Ollama на 127.0.0.1:11434. Открывать API на всех интерфейсах Windows не требуется. На Linux с обычным Docker Engine серверу нужен доступный с Docker-моста интерфейс; при использовании 0.0.0.0 доступ ограничивается файрволом. Порт 11434 не предназначен для публикации в Интернет.

### Загрузка модели

В другом терминале:

```bash
ollama pull qwen3.5:9b-q4_K_M
ollama list
```

Веса занимают около 6,55 ГБ на диске. Дополнительное место нужно для runtime Ollama, Docker-образов и кэшей сборки.

Загрузка выполняется один раз для конкретной машины. Клонирование Git-репозитория не переносит установку Ollama и веса с другого компьютера.

Проверить API и найденную модель в PowerShell:

```powershell
(Invoke-RestMethod 'http://localhost:11434/api/tags').models |
    Where-Object name -eq 'qwen3.5:9b-q4_K_M' |
    Select-Object name, digest
```

На macOS/Linux:

```bash
curl --fail --silent http://localhost:11434/api/tags
```

Список должен содержать нужное имя с digest ниже. Проверка выполняется без генерации.

Запускаторы приложения не устанавливают, не запускают и не перезапускают Ollama; не скачивают модель и не меняют её параметры. Нативное приложение или процесс `ollama serve` должен работать отдельно.

Ожидаемый digest из [config.json](../backend/src/main/resources/assistant/config.json):

```text
56671c2ab9385f9cfcb404638e32cd62d88e3501d44822208363c010179a3c90
```

Java проверяет имя, digest и локальное размещение перед генерацией. Совпадение одного тега без правильных весов недостаточно. Параметры модели и токенизатор остаются прежними; переход из Docker не меняет качество модели автоматически.

## 3. Запуск приложения

Из корня репозитория:

Windows:

```powershell
.\docker\up.ps1
```

Linux/macOS:

```bash
bash docker/up.sh
```

Если PowerShell блокирует локальный файл:

```powershell
powershell -ExecutionPolicy Bypass -File .\docker\up.ps1
```

Запускатор собирает и поднимает только `postgres scoring backend frontend`, ждёт healthcheck и выполняет короткую проверку API Ollama **из контейнера Java**. На отсутствие модели или сервера выводится предупреждение; кабинет остаётся доступным. Проверка `/api/tags` подтверждает сетевую доступность API, а конкретная модель и digest проверяются Java при отправке сообщения.

Открыть [http://localhost:8080](http://localhost:8080) и включить **Java API (/api/v1)**. «Моки OpenAPI» работают в браузере и не проверяют Qwen.

Автоматического прогрева при старте кабинета нет. Первый вопрос загружает веса и обрабатывает полный контекст; он может быть медленнее следующих. После успешного вопроса Java задаёт `keep_alive=10m`: при простое модель может выгрузиться через 10 минут, а следующий вопрос снова потребует загрузки. Это удержание весов, а не готового ответа на будущий вопрос.

Кабинет и контейнеры не прогревают модель и не ждут её загрузки. Качество генерации от наличия прогрева не меняется.

### Повторный запуск после перезагрузки

1. Запустить Docker.
2. Запустить установленное приложение Ollama либо `ollama serve`; вручную запущенный сервер требует открытого терминала.
3. Выполнить `docker/up.ps1` или `bash docker/up.sh` из корня репозитория.
4. Открыть сайт и выбрать Java API. Повторно скачивать веса не требуется, если они сохранены.

Официальный установщик Ollama может настраивать фоновое приложение. Установка из ZIP предоставляет CLI/runtime и сама по себе не создаёт службу или автозапуск.

## 4. Сеть и порты

```text
Браузер → localhost:8080 → Nginx → backend:8080
                                     ├── postgres:5432
                                     ├── scoring:8000
                                     └── host.docker.internal:11434 → Ollama на хосте
```

| Компонент | Адрес |
|---|---|
| Сайт | http://localhost:8080 |
| Swagger | http://localhost:8080/swagger-ui/index.html |
| Здоровье Java | http://localhost:8080/actuator/health |
| PostgreSQL для IDE | localhost:5432 |
| Ollama для Java в Docker | http://host.docker.internal:11434 |
| Ollama из терминала хоста | http://localhost:11434 |

В backend задано `extra_hosts: host.docker.internal:host-gateway` для доступа к хосту, включая Docker Engine на Linux. Ollama должна слушать доступный контейнеру интерфейс; её loopback и localhost внутри Java-контейнера — разные адреса.

Адрес сервера переопределяется `ASSISTANT_OLLAMA_BASE_URL` перед запускатором. Например, для другой доступной машины указывается её HTTP-адрес и порт. Каталог и история по-прежнему передаются Java; браузер не обращается к Ollama напрямую.

Порт сайта переопределяется `APP_PORT`:

```powershell
$env:APP_PORT = '8081'
.\docker\up.ps1
```

```bash
APP_PORT=8081 bash docker/up.sh
```

Nginx проксирует /api, Swagger и health. Его timeout — 90 секунд, бюджет помощника в Java — 60 секунд. Изменение одного Nginx не ускоряет генерацию.

## 5. Оборудование и офисный ПК

Нативная Ollama сама выбирает доступное аппаратное ускорение. Старые флаги запускаторов `-Device`, `--device`, `-Cpu`, `--cpu` больше не используются.

| Окружение | Поведение |
|---|---|
| Mac M-серии | Нативный GPU через Metal при достаточной общей памяти |
| Windows/Linux с поддерживаемым NVIDIA | GPU при подходящем драйвере |
| Windows/Linux с AMD/Intel | Зависит от модели GPU, версии Ollama и поддержки ROCm/Vulkan |
| Без поддерживаемого GPU | CPU; ускорение переносом из Docker не гарантируется |

После вопроса проверить фактическое размещение через `ollama ps`. RAM всего приложения проверяется вместе с процессами хоста: `docker stats` теперь не учитывает нативную модель. Уменьшение показателя Docker Desktop не означает такое же уменьшение всей занятой RAM. Размер модели и контекст сохранены, часть памяти может использоваться в GPU.

Qwen 9B с контекстом требует несколько гигабайт памяти сверх ОС, браузера и четырёх контейнеров. На ПК с 8 ГБ и без GPU быстрые ответы не подтверждены. Основной кредитный путь не загружает модель сам и не ждёт её запуска. Подтверждение требования офисного ПК требует отдельного измерения в среде 8–16 ГБ.

На Windows с RTX 4060 Laptop GPU один полный вопрос через интерфейсный Java API и нативную Ollama занял 15,13 секунды; ответ правильно указал ставку оборотного кредита 24%. Размещение — 14% CPU / 86% GPU, контекст 12 288. Это один запуск на конкретном оборудовании, а не проверка офисного ПК без GPU. Полный CPU-вопрос в прежнем контейнерном варианте превышал 60 секунд. Модель, контекст и таймауты сохранены.

## 6. Данные, образы и остановка

| Хранение | Содержимое |
|---|---|
| Docker-том credit-cabinet-db-data | PostgreSQL: заявки, снимки, сообщения и история |
| Нативное хранилище Ollama | Веса модели; по умолчанию каталог .ollama/models пользователя либо путь установки сервиса |

Веса модели хранятся отдельно от Docker. На текущем Windows-компьютере Ollama 0.40.11 установлена в %LOCALAPPDATA%/Programs/Ollama, веса — в %USERPROFILE%/.ollama/models. Использованы ранее скачанные runtime и точные веса; сеть для повторной загрузки не потребовалась. Путь CLI добавлен в пользовательский PATH и доступен новым терминалам. Сервер запущен фоновым процессом; после перезагрузки его можно поднять командой ollama serve. Логи текущего запуска — %LOCALAPPDATA%/Ollama/credit-cabinet.

Java, React и Python собираются Dockerfile из [backend](backend/Dockerfile), [frontend](frontend/Dockerfile) и [scoring](scoring/Dockerfile). Контекст — корень репозитория, зависимости кэшируются BuildKit. Docker-сборка Java пропускает тесты. Исходники не монтируются: после изменения кода требуется пересборка.

```bash
docker compose stop postgres scoring backend frontend
docker compose start postgres scoring backend frontend
```

Остановка контейнеров не останавливает нативную Ollama. Приложение Ollama завершается средствами ОС; ручной `ollama serve` — Ctrl+C. `ollama stop qwen3.5:9b-q4_K_M` выгружает модель, не удаляя веса.

БД: database/user credit_cabinet, пароль пустой, локальная trust-аутентификация. Flyway применяет V1–V4 при старте Java. Применённые миграции не редактируются. PostgreSQL-том подключён к /var/lib/postgresql. Все прикладные контейнеры используют restart unless-stopped; unhealthy сам по себе не перезапускает процесс.

## 7. Быстрая диагностика

| Симптом | Действие |
|---|---|
| Ollama не найдена | Установить нативное приложение и открыть новый терминал |
| Чат недоступен, кабинет работает | Проверить ollama serve, модель, адрес и доступ к порту из Docker |
| На хосте API отвечает, в Java нет | Проверить OLLAMA_HOST, host.docker.internal и файрвол |
| ASSISTANT_UNAVAILABLE при доступном API | Проверить наличие точного имени модели и digest через /api/tags |
| ASSISTANT_TIMEOUT | Превышен бюджет 60 секунд; проверить ollama ps и загрузку RAM/CPU/GPU |
| TECHNICAL_HOLD заявки | Смотреть backend/scoring; ошибка чата не является этой причиной |
| После смены адреса используется старый сервер | Повторить запускатор для пересоздания backend |
| Порт 8080 занят | Указать APP_PORT |
| Порт 5432 занят | Проверить другой PostgreSQL на хосте |
| Шаблонный мгновенный ответ | Переключить «Моки OpenAPI» на Java API |

```bash
docker compose ps
docker compose logs --tail 60 backend scoring
docker stats --no-stream
ollama ps
```

При обычном запуске контейнеры, БД, образы и нативные веса автоматически не удаляются. Пользовательский сценарий описан в [сценариях демонстрации](../docs/BACKEND_SCENARIOS.md).
