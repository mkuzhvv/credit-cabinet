# Запуск и устройство Docker-конфигурации

Обзор приложения и короткая инструкция находятся в [корневом README](../README.md). Этот документ описывает полный контейнерный запуск, выбор оборудования, сборку образов, хранение данных и диагностику.

Все команды ниже выполняются из корня репозитория, если не указано иное.

## 1. Требования

- Docker Engine либо Docker Desktop с Linux-контейнерами.
- Docker Compose V2 с поддержкой `gpus`, `up --wait` и сборки BuildKit.
- Запущенный Docker daemon; текущий пользователь должен иметь доступ к нему.
- Интернет для получения базовых образов, зависимостей и весов модели при первом запуске.
- Свободное место для образов, кэшей сборки, БД и весов Qwen 9B; достаточная память для модели с контекстом 12 288 токенов.

Для общего запуска не нужны отдельные установки Java, Maven, Node.js, Python или Ollama на хосте. Конфигурация работает без обязательного `.env` и без платного API модели.

В Windows используется Docker Desktop с WSL 2 и Linux-контейнерами. Для ускорения NVIDIA нужен совместимый драйвер Windows с поддержкой GPU в WSL. На Linux для NVIDIA требуется настроенный NVIDIA Container Toolkit; для Vulkan — доступные GPU-устройства `/dev/dri` и подходящий драйвер хоста.

## 2. Первый запуск

### Windows

```powershell
.\docker\up.ps1
```

Если политика PowerShell блокирует локальный файл, допускается разовый запуск без изменения глобальной политики:

```powershell
powershell -ExecutionPolicy Bypass -File .\docker\up.ps1
```

### Linux и macOS

```bash
bash docker/up.sh
```

В обоих случаях запускатор:

1. Собирает образы из единственного корневого `compose.yaml`.
2. Коротким служебным контейнером проверяет доступное ускорение.
3. Передаёт выбранные GPU-параметры в Compose через стандартный ввод.
4. Выполняет `up -d --no-build --wait --wait-timeout 2400`.
5. Выводит фактическое размещение модели через `ollama ps`.

Дополнительные Compose-файлы, локальные конфигурационные файлы и `.env` при этом не создаются. Исходный `compose.yaml` не переписывается. Временный контейнер проверки оборудования удаляется после завершения; пять контейнеров приложения и их тома остаются.

После готовности приложение доступно на [http://localhost:8080](http://localhost:8080). В шапке сайта необходимо включить **«Java API (/api/v1)»**. Режим «Моки OpenAPI» выполняется в браузере и не проверяет серверную цепочку.

### Другой порт сайта

Windows:

```powershell
$env:APP_PORT = '8081'
.\docker\up.ps1
```

Linux/macOS:

```bash
APP_PORT=8081 bash docker/up.sh
```

Публикация изменится на `127.0.0.1:8081`; внутренние порты сервисов останутся прежними. Порт PostgreSQL задан отдельно как `127.0.0.1:5432`.

## 3. CPU, NVIDIA и Vulkan

### Автоматический режим

| Система | Выбор запускатора | Условия и ограничения |
|---|---|---|
| Windows + NVIDIA | CUDA, иначе CPU | Docker Desktop/WSL 2, подходящий драйвер; проверка `nvidia-smi` внутри контейнера |
| Linux + NVIDIA | CUDA, иначе следующая проверка | NVIDIA Container Toolkit и доступ GPU в Docker |
| Linux + AMD/Intel | Vulkan, иначе CPU | `/dev/dri`, драйвер хоста и физический GPU, обнаруженный `vulkaninfo` |
| Windows + AMD/Intel в стандартном Docker Desktop | CPU | Передача GPU этим запускатором не предусмотрена |
| macOS Apple Silicon или Intel | CPU | Модель остаётся в Linux-контейнере; Metal недоступен этой конфигурации |
| Без доступного GPU | CPU | Модель та же; время ответа может превысить бюджет API |

Linux-проверка Vulkan исключает программный рендерер на CPU. Наличие Mesa в образе не заменяет драйвер ядра и доступ к устройствам хоста. Текущий путь AMD/Intel использует Vulkan; ROCm отдельно не настраивается.

### Явный выбор

Windows:

```powershell
.\docker\up.ps1 -Device cpu
.\docker\up.ps1 -Device nvidia
```

Linux:

```bash
bash docker/up.sh --device cpu
bash docker/up.sh --device nvidia
bash docker/up.sh --device vulkan
```

По умолчанию действует `auto`; его можно указать явно через `-Device auto` или `--device auto`. Короткие варианты принудительного CPU — `-Cpu` и `--cpu`.

Если явно запрошенный GPU недоступен, запускатор завершится с ошибкой до изменения работающих контейнеров. Сборка образов выполняется перед этой проверкой.

В NVIDIA-режиме Compose получает `gpus: all`; Vulkan выключен. В Vulkan-режиме передаётся `/dev/dri`, включается `OLLAMA_VULKAN=1`, задаются обнаруженные индексы `GGML_VK_VISIBLE_DEVICES`, CUDA отключается. CPU-режим отключает CUDA и Vulkan.

Обычная команда `docker compose up -d --build` использует базовую конфигурацию без GPU-параметров запускатора. Она подходит для базового запуска, но может пересоздать Ollama без ранее включённого ускорения. Для создания и обновления общего приложения с выбором оборудования используются запускаторы.

### Фактическая скорость

Проверка драйвера подтверждает доступ к GPU, но не гарантирует размещение всей модели в видеопамяти. Это зависит от объёма VRAM, доступной RAM, контекста и других процессов. Возможна частичная выгрузка вычислений на CPU.

```bash
docker compose exec ollama ollama ps
docker stats --no-stream
```

В `ollama ps` столбец `PROCESSOR` показывает размещение модели. Память в `docker stats` и общем показателе Docker Desktop относится к RAM контейнеров, а не к VRAM. Видеопамять проверяется средствами GPU, например `nvidia-smi`. Частичный перенос на GPU не устраняет потребление RAM.

На Windows с RTX 4060 наблюдалось размещение 86% GPU / 14% CPU; первый полный запрос занял около 29 секунд, следующий — около 1,5 секунды. CPU-проверка первого вопроса превысила 60 секунд и вернула `ASSISTANT_TIMEOUT`. Результаты зависят от запроса и состояния кэша. Реальный AMD/Intel через Vulkan и macOS аппаратно не проверялись.

## 4. Сервисы и образы

Проект Compose называется `credit-cabinet-dev`. Это группа из пяти отдельных контейнеров.

| Сервис | Образ | Порт внутри сети | Публикация на хост |
|---|---|---|---|
| `postgres` | `postgres:18.6-alpine` | 5432 | `127.0.0.1:5432` |
| `scoring` | `credit-cabinet-scoring:local` | 8000 | Нет |
| `ollama` | `credit-cabinet-llm:local` | 11434 | Нет |
| `backend` | `credit-cabinet-backend:local` | 8080 | Нет |
| `frontend` | `credit-cabinet-frontend:local` | 80 | `127.0.0.1:8080` по умолчанию |

Публикация на `127.0.0.1` ограничивает доступ текущим компьютером. Внутри сети Compose сервисы используют имена `postgres`, `scoring`, `ollama`, `backend`. `localhost` внутри контейнера обозначает сам этот контейнер.

### Файлы

```text
compose.yaml
docker/
├── README.md
├── .gitattributes
├── up.ps1
├── up.sh
├── backend/
│   ├── Dockerfile
│   └── Dockerfile.dockerignore
├── frontend/
│   ├── Dockerfile
│   ├── Dockerfile.dockerignore
│   └── nginx.conf
├── scoring/
│   ├── Dockerfile
│   └── Dockerfile.dockerignore
└── llm/
    ├── Dockerfile
    ├── Dockerfile.dockerignore
    ├── start.sh
    └── check-vulkan.sh
```

Все сборки используют корень репозитория как context. Поэтому `COPY` обращается к `backend/`, `frontend/`, `ml/scoring/` и `docker/`.

| Dockerfile | Сборка и выполнение |
|---|---|
| [backend/Dockerfile](backend/Dockerfile) | Maven 3.9.16 + JDK 21 собирают JAR; JRE 21 запускает его от пользователя `app`. Тесты при сборке образа пропущены. |
| [frontend/Dockerfile](frontend/Dockerfile) | Node.js 24 выполняет `npm ci` и Vite build; Nginx 1.28 отдаёт готовый `dist`. Vite не работает в конечном контейнере. |
| [scoring/Dockerfile](scoring/Dockerfile) | Python 3.12.14 устанавливает зависимости из закреплённого `requirements.txt`, запускает HTTP-сервис от пользователя `app`. |
| [llm/Dockerfile](llm/Dockerfile) | Расширяет Ollama 0.40.11: добавляет curl, jq, Vulkan tools, Mesa и подготовку модели. |

`Dockerfile.dockerignore` каждого компонента ограничивает сборочный контекст нужными исходниками. Git, `node_modules`, `target`, виртуальные окружения и локальные веса не копируются. BuildKit кэширует зависимости Maven, npm и pip между сборками. Исходники хоста не монтируются в выполняемые контейнеры: изменения кода требуют пересборки.

## 5. Порядок старта и подготовка модели

PostgreSQL, скоринг и Ollama запускаются первыми. Java ждёт успешных healthcheck всех трёх; фронтенд ждёт Java.

`docker/llm/start.sh` внутри контейнера:

1. Удаляет старую отметку готовности и запускает `ollama serve`.
2. Ожидает HTTP API Ollama.
3. Читает имя модели и digest из конфигурации.
4. Скачивает модель через `ollama pull`, если нужного имени ещё нет в томе.
5. Проверяет digest и отсутствие удалённого размещения модели.
6. Выполняет прогрев с `num_ctx=12288`, `think=false`, `keep_alive=10m`.
7. Создаёт `/tmp/ollama-ready` и оставляет сервер работать.

Конфигурация копируется из [assistant/config.json](../backend/src/main/resources/assistant/config.json), используемого Java. Веса не входят в Docker-образ: они скачиваются в постоянный том.

Текущая модель — `qwen3.5:9b-q4_K_M`, ожидаемый digest:

```text
56671c2ab9385f9cfcb404638e32cd62d88e3501d44822208363c010179a3c90
```

Если имя уже существует с другим digest, подготовка останавливается; подмена модели не принимается автоматически. Ошибка скачивания или прогрева также не создаёт отметку готовности.

Healthcheck Ollama проверяет отметку и HTTP API. `start_period: 40m` позволяет закончить первую загрузку; успешная проверка переводит сервис в healthy сразу, без обязательного ожидания 40 минут. Запускатор ожидает максимум 2400 секунд. Прогрев имеет отдельный предел 300 секунд.

Прогрев с пустым списком сообщений загружает веса, но не обрабатывает полный каталог и вопрос приложения. Первый реальный ответ может быть медленнее последующих. Через 10 минут простоя модель может выгрузиться; наличие отметки готовности не означает постоянное размещение весов в памяти.

Все сервисы имеют `restart: unless-stopped`. Эта политика перезапускает завершившийся процесс, но сама по себе не пересоздаёт контейнер только из-за статуса unhealthy. `depends_on` задаёт порядок запуска и не заменяет обработку последующих сбоев в приложении.

## 6. Сеть и HTTP

```text
Браузер → localhost:8080 → frontend:80 (Nginx)
                              ├── статические файлы React
                              └── /api/* → backend:8080
                                               ├── postgres:5432
                                               ├── scoring:8000
                                               └── ollama:11434
```

[Nginx](frontend/nginx.conf) отдаёт SPA и проксирует `/api/`, Swagger, `/v3/api-docs` и `/actuator/health`. `/health` проверяет сам Nginx. Для адреса Java используется DNS Docker с повторным разрешением после пересоздания контейнера.

Cookie и CSRF работают с одним адресом сайта. Время ожидания upstream в Nginx — 90 секунд; бюджет чата в Java — 60 секунд. Увеличение только Nginx timeout не изменит дедлайн помощника.

Java получает внутренние адреса через переменные Compose: `DB_URL`, `SCORING_BASE_URL`, `ASSISTANT_OLLAMA_BASE_URL`. `SERVER_FORWARD_HEADERS_STRATEGY=framework` включает обработку переданных Nginx заголовков.

## 7. Данные и миграции

| Том | Содержимое | Путь в контейнере |
|---|---|---|
| `credit-cabinet-db-data` | PostgreSQL: заявки, снимки, диалоги, история | `/var/lib/postgresql` |
| `credit-cabinet-ollama-data` | Скачанные модели Ollama | `/root/.ollama` |

Для PostgreSQL 18 используется родительский каталог `/var/lib/postgresql`; это соответствует текущему Compose. Изменение пути монтирования без переноса существующих данных не требуется.

Параметры локальной БД:

| Параметр | Значение |
|---|---|
| Host / Port для IDE | `localhost:5432` |
| Database / User | `credit_cabinet` |
| Password | Пустой |
| Authentication | `trust`, только демонстрационная локальная конфигурация |
| Container name | `credit-cabinet-db` |

Flyway автоматически применяет V1–V4 при запуске Java. Схема содержит 10 прикладных таблиц и `flyway_schema_history`. Hibernate проверяет соответствие через `ddl-auto=validate`, но не создаёт таблицы вместо миграций. Инициализация существующего тома PostgreSQL не повторяется от простой смены переменных окружения.

Применённые SQL-миграции не редактируются: Flyway хранит их контрольные суммы. Изменение схемы оформляется следующей миграцией. `repair` исправляет метаданные, но не выполняет за изменённый SQL преобразование таблиц.

Остановка и пересоздание контейнера с тем же томом сохраняют данные. `docker compose down` удаляет контейнеры и сеть; `down -v` дополнительно удаляет тома, включая БД и скачанную модель. Для повседневной работы достаточно `stop` / `start`.

Сессии Java хранятся в памяти и после перезапуска сбрасываются. Сохранённые заявки и диалоги остаются в PostgreSQL.

## 8. Повседневные команды

| Задача | Команда |
|---|---|
| Состояние пяти сервисов | `docker compose ps` |
| Последние логи | `docker compose logs --tail 100` |
| Логи обработки заявок | `docker compose logs --tail 100 backend scoring` |
| Логи модели | `docker compose logs --tail 100 ollama` |
| Следить за Java | `docker compose logs -f backend` |
| Потребление RAM/CPU | `docker stats --no-stream` |
| Размещение модели | `docker compose exec ollama ollama ps` |
| Остановить, сохранив контейнеры | `docker compose stop` |
| Запустить сохранённые контейнеры | `docker compose start` |
| Перезапустить только Java | `docker compose restart backend` |
| Поднять только БД для IDE | `docker compose up -d --wait postgres` |
| Открыть SQL-консоль | `docker compose exec postgres psql -U credit_cabinet -d credit_cabinet` |

`start` сохраняет созданные GPU-настройки, но не пересобирает исходники и не применяет новую конфигурацию. После него требуется дождаться healthy в `docker compose ps`. `restart` также не обновляет образ. После изменения кода повторный запуск `up.ps1` / `up.sh` собирает изменённые слои и обновляет нужные контейнеры, заново выбирая оборудование.

## 9. Устранение проблем

| Симптом | Проверка и действие |
|---|---|
| Docker недоступен | Проверить, что Docker запущен, выбран Linux engine и у пользователя есть доступ к daemon: `docker info`. |
| Порт 8080 занят | Задать `APP_PORT` перед запускатором. |
| Порт 5432 занят | Найти другой локальный PostgreSQL/старый контейнер. Текущий Compose публикует БД на фиксированном порту. |
| Ollama долго starting | Посмотреть `docker compose logs -f ollama`: скачивание модели, digest, прогрев. Первый запуск существенно дольше повторного. |
| NVIDIA не выбрана | Проверить драйвер, WSL 2 либо Container Toolkit и вывод явного режима `nvidia`. Хостовый `nvidia-smi` сам по себе не доказывает доступ GPU из Docker. |
| Vulkan не выбран | Проверить Linux, `/dev/dri`, драйвер и явный режим `vulkan`. Программный Vulkan-рендерер не принимается за GPU. |
| Контейнер завершился / OOMKilled | Проверить логи и `docker inspect` соответствующего контейнера, лимиты памяти Docker/WSL и доступную RAM/VRAM. Смена режима CPU/GPU не уменьшает размер самой модели. |
| `504 ASSISTANT_TIMEOUT` | Вызов превысил 60 секунд. Проверить размещение модели, загрузку CPU/GPU и прогрев. CPU может быть недостаточно быстрым. Ошибка чата не означает кредитный отказ. |
| `502 ASSISTANT_INVALID_RESPONSE` | Проверить логи Java, digest модели, формат и полноту ответа. Невалидный ответ не сохраняется как успешный. |
| `503 ASSISTANT_UNAVAILABLE` | Проверить Ollama и её readiness; Java не обращается к нативной Ollama на хосте. |
| `TECHNICAL_HOLD` | Проверить причину в заявке и логи `backend scoring`; после устранения сбоя доступен повтор рассмотрения. |
| Ошибка checksum Flyway | Сравнить применённую миграцию с Git; восстановить исходный файл и оформить новую миграцию. Пересоздание контейнера с прежним томом checksum не сбрасывает. |
| UI отвечает шаблонами мгновенно | Проверить, что выбран Java API, а не «Моки OpenAPI». |
| Ошибка загрузки Maven/npm/pip или образа | Проверить интернет, DNS, прокси и доступ к реестру из Docker. Успешная сборка с локальным кэшем не доказывает доступность всех репозиториев на другой сети. |
| Страница без оформления | Проверить доступ браузера к внешним Tailwind CSS и Google Fonts. |
| Предупреждение о ранее созданном томе | Сверить имя и содержимое тома. Само предупреждение не требует удаления БД или модели. |

Для просмотра основных компонентов достаточно открыть сайт, Swagger и `/actuator/health`, затем выполнить сценарий [демонстрации](../docs/BACKEND_SCENARIOS.md). Статус healthy подтверждает готовность сервиса по его healthcheck, но не гарантирует время генерации полного ответа модели или успешное выполнение любого бизнес-сценария.
