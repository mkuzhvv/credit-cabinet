# Интерфейс и интеграция с Java API

Исходники находятся в [frontend](../frontend/). Общий запуск выполняется через [Docker](../docker/README.md); Nginx отдаёт готовую Vite-сборку.

## 1. Экраны

| Файл | Ответственность |
|---|---|
| [App.jsx](../frontend/src/App.jsx) | Режим API, загрузка кабинета, текущая заявка и взаимодействие экранов |
| [ProductsPage.jsx](../frontend/src/pages/ProductsPage.jsx) | Пять продуктов серверного каталога и недавние заявки |
| [ApplicationPage.jsx](../frontend/src/pages/ApplicationPage.jsx) | Поля выбранного продукта, сохранение, отправка и показ результата |
| [Header.jsx](../frontend/src/components/Header.jsx) | Навигация, состояние заявки и переключение API |
| [AssistantWidget.jsx](../frontend/src/components/AssistantWidget.jsx) | Диалог, история, вопросы по полям и выбор рекомендации |
| [client.js](../frontend/src/api/client.js) | HTTP, сессия, CSRF, ключи команд, преобразование форматов и моки |

Стек: React 18, Vite, Tailwind CSS и Lucide. Изображение и основные компоненты оформления находятся в исходниках интерфейса. Tailwind CSS и Google Fonts также загружаются внешними ресурсами страницы; полностью автономная работа без сети не обеспечивается.

## 2. Режимы API

Режим сохраняется в `localStorage.alfa_api_mode`. Если настройки ещё нет, выбран `mock`.

**Моки OpenAPI** имитируют контракт в браузере: каталог, заявки, исходы и шаблонные реплики. Это позволяет показать страницы без серверов, но не подтверждает работу Java, Python и Qwen.

**Java API (/api/v1)** использует настоящий сервер. Интерфейс последовательно получает CSRF, выполняет демовход, обновляет токен и загружает профиль. Параллельные компоненты используют общую инициализацию сессии.

Базовый путь HTTP — `/api/v1`. В контейнерах его проксирует Nginx; при Vite-разработке `/api` проксируется в `http://localhost:8080` по [vite.config.js](../frontend/vite.config.js).

## 3. Форма и деньги

Полная форма содержит девять ключей:

```json
{
  "amount": "100000.00",
  "termMonths": 3,
  "averageMonthlyInflow": "10000000.00",
  "averageMonthlyOutflow": "800000.00",
  "financingPurpose": null,
  "projectBudget": null,
  "trancheTermMonths": null,
  "governmentContract": null,
  "cashBalance": "1000000.00"
}
```

Это пример оборотного кредита. У LONG_TERM заполняются цель и бюджет, у REVOLVING_LINE — срок транша, у GOVERNMENT_CONTRACT_LINE — объект контракта. Неприменимые поля передаются null.

Клиент сохраняет копейки при преобразовании ввода. Пустое значение не превращается в `"0.00"`. Суммы API представлены строками; ставки и аннуитетный расчёт показываются согласно механике продукта. Овердрафт и линии не представляются обычным аннуитетом на весь срок лимита.

Период показателей поступает с сервера. Для овердрафта это 3 месяца, оборотного кредита и возобновляемой линии — 6, остальных продуктов — 12.

## 4. Сохранение и отправка

Изменения формы проходят через последовательную очередь сохранений. Каждый PUT содержит `expectedVersion`. Новый ввод не должен перезаписываться ответом на более раннее сохранение.

При `409 VERSION_CONFLICT` интерфейс получает актуальную заявку и сообщает о конфликте; пользователь заново вносит нужные изменения. Автоматическое объединение разных версий не выполняется.

Отправка использует сохранённую форму, текущие версии заявки и условий продукта. После `202` интерфейс опрашивает заявку и показывает состояние, причины, уточнение либо условия одобрения. Доступные действия определяет `allowedActions` сервера.

Для нового действия создаётся новый Idempotency-Key. При неопределённом сетевом результате сохраняется прежний ключ: повтор должен получить прежний ответ, а не создать второй эффект.

## 5. Восстановление кабинета

Текущая заявка восстанавливается по сохранённому идентификатору и перечитывается через API. Состояние моков и Java API разделено. Сами заявки и диалоги реального режима находятся в PostgreSQL; браузерное хранилище содержит ссылки и настройки интерфейса.

Перезапуск Java требует новой демосессии. Это не удаляет бизнес-данные. Смена режима API сбрасывает неподходящий контекст загрузки, чтобы ответы старого режима не попадали в новый экран.

## 6. Помощник

Чат становится доступен после подготовки сессии. История загружается страницами по `afterSequence` и `limit`; отображение не ограничивается только последней страницей.

Для вопроса по полю передаются разрешённые идентификаторы заявки, продукта и поля. Каталог и значения Java получает сама. Ответ отображается из `assistantMessage.text`; `recommendedProductCode` позволяет показать отдельное действие выбора продукта.

Двойная отправка блокируется на время запроса. При ошибке текст сохраняется для повтора. Чат не меняет форму автоматически и не блокирует независимое рассмотрение заявки.

## 7. Разработка и проверки

Из `frontend/`, при установленном Node.js и npm:

```bash
npm ci
npm run dev
```

Vite обычно доступен на `http://localhost:5173`. Для настоящих API-запросов должен отвечать `http://localhost:8080`, например общий Docker-запуск. Без серверов остаётся режим моков.

```bash
npm run lint
npm test
npm run build
```

[Тесты](../frontend/test/frontend.test.js) проверяют компоненты и API-взаимодействие с управляемыми ответами: продуктовые поля, денежные значения, сохранение, конфликты, повтор команды и подготовку чата. Реальные сценарии с сервисами описаны в [порядке демонстрации](BACKEND_SCENARIOS.md).
