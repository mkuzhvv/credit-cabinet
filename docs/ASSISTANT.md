# Локальный ИИ-помощник

Помощник объясняет продукты и поля заявки. Рабочий путь приложения: **React → Java → Spring AI → Ollama → Qwen → Java → React**. Ollama основного запуска работает нативно на хосте, отдельно от четырёх контейнеров приложения. Дополнительного Python HTTP-сервиса чата нет.

Запуск и оборудование: [Docker](../docker/README.md). Форматы: [LLM-контракт](contracts/llm/README.md).

## 1. Назначение

Помощник использует переданный каталог, объясняет разницу продуктов и может вернуть код рекомендации. Пользователь выбирает предложенный продукт отдельным действием.

Генерация не меняет поля, не отправляет заявку, не проверяет БКИ и не одобряет финансирование. Рассмотрение работает отдельным контуром Java/Python. Ошибка чата не должна превращаться в ошибку или отказ по заявке.

## 2. Где используется Spring AI

[OllamaAssistantGateway](../backend/src/main/java/com/creditcabinet/assistant/integration/OllamaAssistantGateway.java) создаёт HTTP-клиент и `OllamaChatModel`, затем передаёт `Prompt` со структурированным форматом ответа. Регистрация шлюза, исполнителя и свойств находится в [AssistantConfig](../backend/src/main/java/com/creditcabinet/config/AssistantConfig.java).

[AssistantService](../backend/src/main/java/com/creditcabinet/assistant/service/AssistantService.java) ограничивает длительность операции и координирует подготовку/сохранение. [AssistantStateService](../backend/src/main/java/com/creditcabinet/assistant/service/AssistantStateService.java) отвечает за БД, права и захваты.

## 3. Конфигурация модели

Рабочие ресурсы Java находятся в [backend/src/main/resources/assistant](../backend/src/main/resources/assistant/). Java использует эти ресурсы при обращении к нативной Ollama.

| Параметр | Значение |
|---|---|
| Модель | `qwen3.5:9b-q4_K_M` |
| Digest | `56671c2ab9385f9cfcb404638e32cd62d88e3501d44822208363c010179a3c90` |
| Промпт | `assistant-v5.0.0` |
| Контекст / ответ | 12 288 / до 512 токенов |
| Вход / выход | AssistantContext v2 / AssistantReply v1 |
| Temperature / seed | 0 / 42 |
| Think / stream | Выключены |
| Keep alive | 10 минут |
| Бюджет Java API | 60 секунд |
| Захват диалога и команды | 75 секунд |

`timeout_seconds=180` в JSON относится к Python-стенду. Он не изменяет бюджет HTTP-операции Java.

Перед генерацией проверяются локальное размещение, имя и digest модели через API Ollama. Смена тега с тем же именем, но другими весами требует согласованного обновления конфигурации.

## 4. Как Java собирает контекст

[AssistantContextFactory](../backend/src/main/java/com/creditcabinet/assistant/service/AssistantContextFactory.java) проверяет доступ к заявке и формирует:

- активный каталог и условия выбранного продукта;
- определения полей из ресурсов Java;
- выбранные коды продукта и поля;
- статус, расчётную дату, финансовый период и разрешённые значения заявки;
- историю успешных сообщений.

Без заявки `application=null`: выбор продукта работает и до создания черновика. Для отправленной заявки условия выбранного продукта берутся из её сохранённого снимка. Остальные продукты представлены текущим активным каталогом.

Без выбранного поля передаются базовые сумма и срок; вопрос о поле добавляет его значение и необходимые зависимости. Полный кредитный отчёт и номер госконтракта исключены. Браузер не присылает собственный каталог или историю вместо серверной.

## 5. Промпт и токены

[AssistantPromptBuilder](../backend/src/main/java/com/creditcabinet/assistant/integration/AssistantPromptBuilder.java) создаёт системное сообщение с JSON-контекстом, помеченным как данные, и версионированными правилами. Следом идут история с ролями и текущий вопрос.

Используется закреплённый токенизатор Qwen с проверкой SHA-256. Для входа оставляется `12288 − 512 − 512 = 11264` токена; дополнительно учитывается обрамление сообщений.

В модель попадает до 20 предыдущих сообщений. При нехватке бюджета удаляются старые полные пары USER/ASSISTANT. Обязательный контекст и текущий вопрос не обрезаются молча: если они не помещаются, возвращается техническая ошибка. История PostgreSQL при этом сохраняется полностью.

## 6. Структурированный ответ и проверка фактов

Модель должна вернуть ровно:

```json
{
  "answer": "Для разовой закупки подходит оборотный кредит.",
  "recommendedProductCode": "WORKING_CAPITAL"
}
```

В Ollama передаётся JSON Schema с допустимыми кодами каталога и null. Java проверяет JSON, обязательные/лишние поля, непустой текст, предел длины, допустимый код, отсутствие HTML, tool calls и незавершённой генерации.

[AssistantGrounding](../backend/src/main/java/com/creditcabinet/assistant/integration/AssistantGrounding.java), версия `facts-v3-java-1`, применяет правила для ставок, сумм, сроков и механики продукта по типизированному ProductTerms. Это обеспечивает конкретные проверки каталожных фактов; произвольный свободный текст модели не получает абсолютной гарантии правильности.

Системный промпт и structured output дополняют проверку Java, но не заменяют её.

## 7. Сохранение и повторы

Создание диалога и отправка сообщения используют Idempotency-Key. Один диалог допускает одну активную генерацию.

Подготовка и резервирование выполняются короткой транзакцией. Вызов модели идёт вне транзакции. После успешной проверки Java атомарно сохраняет USER и ASSISTANT, назначает последовательные sequence и записывает метаданные генерации.

Метаданные включают версии схем/модели/промпта, параметры и минимальные ссылки на контекст. При ошибке пара не сохраняется, ввод остаётся в интерфейсе для повтора. Запоздалый ответ после утраты токена не записывается.

| Ошибка | Значение |
|---|---|
| `503 ASSISTANT_UNAVAILABLE` | Модель или транспорт недоступны |
| `504 ASSISTANT_TIMEOUT` | Превышен общий бюджет |
| `502 ASSISTANT_INVALID_RESPONSE` | Ответ не прошёл проверку |
| `409` для занятой команды/диалога | Требуется дождаться текущей операции либо повторить исходную команду |

## 8. Материалы Python-стенда

[ml/llm](../ml/llm/) содержит `assistant.py`, `chat.py`, `grounding.py`, `setup_model.py`, промпт, каталог примеров и схемы. Они служат для разработки и исследования поведения помощника; Java не запускает эти файлы на запрос.

`products.json` и `fields.json` стенда не определяют тарифы и поля рабочего API. Источники приложения — PostgreSQL/ProductTerms и определения Java. Примеры стенда могут отличаться по названиям полей; перенос изменений требует сверки с текущими контрактами.

Копии схем в `ml/llm/contracts` связаны с источником через `SOURCE.json`. Нормативные API-материалы находятся в [docs/contracts](contracts/README.md).

## 9. Качество и скорость

[Контрольные вопросы](contracts/llm/acceptance-cases.json) задают смысловые ожидания. [AssistantModelAcceptanceTest](../backend/src/test/java/com/creditcabinet/assistant/AssistantModelAcceptanceTest.java) включается отдельно через `assistant.real-model=true` и использует настоящие БД/модель. Он не выполняется как часть обычной сборки и не заменяет проверку на целевом оборудовании.

Скорость зависит от полного контекста, загрузки модели, GPU/CPU и кэшей. В основном запуске предварительный прогрев не выполняется; первый вопрос может быть медленнее. Прежний контейнерный CPU-вопрос превысил 60 секунд. Один полный нативный запрос на Windows/RTX 4060 занял 15,13 секунды; модель распределена на 86% GPU и 14% CPU. Ответ о ставке 24% проверен через Java API. Одинаковая скорость на всех компьютерах не гарантируется.

Текущая реализация не использует streaming. Уменьшение контекста, дополнительный прогрев полного промпта и изменение параметров KV-кэша не включены автоматически в описанный запуск.
