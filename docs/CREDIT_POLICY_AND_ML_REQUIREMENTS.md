# Кредитная политика и формальная оценка

Документ описывает действующие правила демонстрационного приложения. Условия не являются тарифами банка. Источник каталога Java — [V3](../backend/src/main/resources/db/migration/V3__seed_credit_products.sql), расчёт Python — [SCORING.md](SCORING.md).

Общие демонстрационные условия: ИП и ООО, зарегистрированные в РФ, рубли, отсутствие обязательных залога, поручительства, страховки и комиссии за выдачу/обслуживание. Досрочное погашение описано без комиссии, с процентами за фактическое использование. Сервис не выполняет KYC, оформление обеспечения или обслуживание договора.

| Овердрафт | Лимит к счёту, автоматическое погашение поступлениями; задолженность полностью закрывается за 30 дней с первого использования, новые расходы срок не продлевают |

Срок лимита овердрафта 12 месяцев отличается от срока долга 30 дней; срок линии 24 месяца — от срока транша. Госконтрактная линия не предназначена для участия в закупке или обеспечения заявки.

## 2. Поля формы

Общие поля при отправке: `amount`, `termMonths`, `averageMonthlyInflow`, `averageMonthlyOutflow`, `cashBalance`.

`amount` — сумма разовой выдачи либо общий лимит. `cashBalance` — свободные собственные деньги до нового кредита, без недоступных средств. Существующие платежи по обязательствам уже входят в среднемесячные расходы.

Дополнительные поля:

- LONG_TERM: `financingPurpose`, `projectBudget`.
- REVOLVING_LINE: `trancheTermMonths`.
- GOVERNMENT_CONTRACT_LINE: `governmentContract` с `lawCode=44_FZ`, номером, стоимостью, авансом, датами исполнения и окончательной оплаты.

Неприменимые поля равны null. Черновик допускает незаполненные применимые поля. Ноль — известное значение, null — отсутствие данных. Денежные значения неотрицательны и передаются строками с двумя знаками; сумма финансирования и положительные продуктовые величины проверяются при submit.

Для LONG_TERM бюджет должен быть положительным. Отдельного ограничения `amount <= projectBudget` в текущей политике нет.

## 3. Даты и динамические пределы

`calculationDate` — UTC-дата создания черновика. Финансовый период включает 3/6/12 полных календарных месяцев перед её месяцем. Он не сдвигается при редактировании, submit или retry.

`asOfDate` — UTC-дата принятия исходной попытки submit. По ней рассчитываются возраст бизнеса и `plannedEndDate = asOfDate.plusMonths(termMonths)`. Новый submit после уточнения получает новую asOfDate; технический retry сохраняет исходную.

### Овердрафт

```text
maxAllowedAmount = min(1 000 000.00, 0.30 × averageMonthlyInflow)
```

Счёт и регулярность поступлений берутся из серверного профиля компании. В демо это подготовленные признаки, а не анализ реальной выписки. Нулевые поступления не позволяют обойти нулевой предел подтверждением значения.

### Госконтракт

```text
maxAllowedAmount = min(10 000 000.00, 0.70 × (contractAmount − advanceAmount))
```

Стоимость положительна, `0 <= advanceAmount <= contractAmount`. Для стоимости 10 млн и аванса 2 млн предел равен 5,6 млн.

Дата исполнения не раньше asOfDate; дата окончательной оплаты согласована с исполнением. Плановый конец финансирования не раньше завершения исполнения и не позже окончательной оплаты плюс 30 календарных дней. Срок остаётся в диапазоне 1–12 месяцев.

Динамические денежные пределы округляются вниз до копейки. Введённые суммы молча не округляются и не уменьшаются. Превышение или отсутствие допустимой суммы даёт ошибку поля `422`, а не отказ по риску.

## 4. Порядок рассмотрения

1. Проверить доступ и успешный идемпотентный повтор.
2. Проверить состояние, версии, полноту формы, диапазоны, даты и ответы на уточнения.
3. Одной транзакцией создать попытку и снимок, закрепить условия/политику, перевести заявку в CHECKING, сохранить событие и ответ 202.
4. В фоне проверить возраст бизнеса и банковские требования продукта.
5. Получить и сохранить кредитный отчёт.
6. При положительной текущей просрочке завершить отказом.
7. При неподтверждённых нулевых поступлениях запросить уточнение.
8. Вызвать Python по сохранённым признакам и проверить ответ.
9. Применить порог и атомарно сохранить итог.

Ошибки формы не создают попытку и не вызывают внешние компоненты. Недоступность источника или неверный ответ Python дают TECHNICAL_HOLD, а не кредитный отказ.

## 5. Причины и уточнение

| Причина / исход | Значение |
|---|---|
| BUSINESS_TOO_YOUNG | Не выполнен минимальный возраст бизнеса |
| SETTLEMENT_ACCOUNT_REQUIRED | Нет требуемого счёта |
| REGULAR_INFLOW_REQUIRED | Нет требуемой регулярности поступлений |
| CURRENT_OVERDUE_DEBT | Есть текущая просрочка; проверяется до Python |
| ZERO_INFLOW_CONFIRMATION / NEEDS_INFO | Требуется подтверждение или исправление нулевых поступлений |
| RISK_THRESHOLD_EXCEEDED | Не пройдены расчётные правила платёжеспособности Python |

Согласованное уточнение — `form.averageMonthlyInflow`. Для `CONFIRM_VALUE` подтверждается сохранённое `0.00`. Для `VALUE_CORRECTED` сначала сохраняется положительное значение, затем отправляется ответ с ID вопроса.

Неполная анкета не является NEEDS_INFO. Подтверждение нуля не гарантирует одобрение и не отменяет предел продукта. Ответ на устаревшее или неприменимое уточнение не принимается.

## 6. Политика Python и версии

Алгоритм использует стресс поступлений 10%, коэффициент нового платежа 1,30 и резерв в один месяц расходов. Подробные формулы и продуктовые сценарии — в [SCORING.md](SCORING.md).

Закреплённая связка:

| Артефакт | Версия |
|---|---|
| Backend OpenAPI | 0.5.0 |
| Снимок исходных данных | 2 |
| Политика Java | credit-cashflow-v1 |
| Scoring OpenAPI / признаки | 0.4.0 / 4 |
| Алгоритм | rules-cashflow-v1-59fdb57552ca |
| Порог Java | 0.50 |
| Кредитный отчёт | 1 |

Python возвращает только 0 или 1: результат ниже 0,50 допускает одобрение при выполнении остальных правил. Это формальная оценка, а не вероятность дефолта.

При техническом retry используются исходные данные и сохранённый отчёт при наличии. Продолжение после уточнения создаёт новую попытку с актуальными данными и заново получает отчёт для неё. Исторические снимки не переписываются.

## 7. Ограничения

Сведения компании и кредитная история синтетические. БКИ, реестр закупок, ФНС и реальные выписки не запрашиваются. Модель риска не обучена на банковских исходах. Решение APPROVED означает демонстрационное одобрение условий; выдача, подписание и расчёты с клиентом за пределами приложения.
