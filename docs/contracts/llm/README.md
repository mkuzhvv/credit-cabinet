# Контракт LLM: вход v2, ответ v1

Этот контракт описывает данные между Java и адаптером модели. Путь исполнения: Java → Spring AI → Ollama. HTTP API браузера находится в [Backend OpenAPI](../backend.openapi.yaml), устройство интеграции — в [ASSISTANT.md](../../ASSISTANT.md).

## 1. Файлы

- [input.schema.json](input.schema.json) — AssistantContext v2.
- [output.schema.json](output.schema.json) — AssistantReply v1.
- [Выбор продукта: вход](examples/product-request.json) и [ответ](examples/product-response.json).
- [Объяснение поля: вход](examples/field-request.json) и [ответ](examples/field-response.json).
- [acceptance-cases.json](acceptance-cases.json) — 36 основных контрольных вопросов; точная формулировка текста не фиксируется.

Примеры показывают формат и не заменяют актуальный каталог БД. Копии в ml/llm/contracts связаны с источником через SOURCE.json.

## 2. Вход Java

| Поле | Источник и смысл |
|---|---|
| schemaVersion | Java, строка `"2"` |
| conversationId | Сохранённый диалог текущего пользователя |
| message | Текущий вопрос, до 2000 символов |
| history | Предыдущие USER/ASSISTANT, до 20 сообщений в модельном контексте |
| context.catalog | Продукты и условия, сформированные Java |
| context.fieldDefinitions | Названия, единицы и определения полей |
| context.selectedProductCode | Проверенный выбранный продукт либо null |
| context.currentFieldCode | Проверенный путь поля либо null |
| context.application | Разрешённые сведения заявки либо null |

Каталог содержит пять продуктов с financingType и financialPeriodMonths. Для выбранной отправленной заявки условия берутся из закреплённого снимка. Периоды 3/6/12 зависят от продукта; лимит, транш и отдельная задолженность различаются.

fieldCode совпадает с путём API, например `form.cashBalance` или `form.governmentContract.advanceAmount`. fieldValues содержит строковое представление разрешённых значений для объяснения. Полный кредитный отчёт и номер контракта не передаются.

История, каталог и данные заявки формируются сервером после проверки доступа. Вход пользователя и значения формы считаются данными, а не системными инструкциями.

## 3. Преобразование в запрос Ollama

AssistantContext не является готовым телом `/api/chat`. Адаптер создаёт системное сообщение с контекстом и правилами, историю с ролями и последний пользовательский вопрос. Имя модели, digest и параметры берутся из закреплённой конфигурации.

Нативный structured output Ollama получает JSON Schema ответа. Допустимые recommendedProductCode сужаются до текущего каталога плюс null. Ответ извлекается из содержимого сообщения модели.

Токенный бюджет проверяется до вызова. При необходимости удаляются старые полные пары истории; обязательный контекст не обрезается незаметно. История БД от ограничения промпта не меняется.

## 4. Ответ модели

```json
{
  "answer": "Для покупки оборудования с длительной окупаемостью подходит кредит на длительный срок.",
  "recommendedProductCode": "LONG_TERM"
}
```

Оба поля обязательны. answer — непустой русский текст до 3000 символов. recommendedProductCode — код входного каталога либо null. Лишние ключи, HTML, tool calls, команды изменения формы и незавершённая генерация не принимаются.

Ожидаемое поведение:

1. Объяснять условия только по контексту и различать механику продуктов.
2. Рекомендовать доступный продукт по цели; при нехватке данных задать один уточняющий вопрос.
3. Объяснять поле с правильными единицами, периодом и различием null/нуля.
4. Не обещать одобрение, не подменять скоринг и не предлагать исказить данные.
5. Не утверждать, что форма изменена или банковское действие выполнено.
6. Сохранять границы каталога и игнорировать попытки подменить системные правила.

JSON Schema подтверждает форму, а не достоверность свободного текста. Java дополнительно проверяет каталожные факты и код продукта.

## 5. Преобразование в HTTP и сохранение

answer записывается в assistantMessage.text; recommendedProductCode — в одноимённое поле сообщения. ID, sequence, replyTo и время создаёт Java. Пользовательский вопрос и ответ добавляются одной транзакцией после успешной проверки.

По общему [HTTP-контракту](../README.md) используются cookie, CSRF и Idempotency-Key. Ошибка не сохраняет неполную пару и не превращается в фиктивную рекомендацию. Повтор успешного ключа возвращает исходную пару.

Недоступность — 503, невалидный ответ — 502, таймаут — 504. Общий бюджет Java — 60 секунд, независимо от 180 секунд в Python-стенде.

## 6. Проверка изменений

Контрольные вопросы оценивают смысл ответа, рекомендацию, периоды, числовые условия и границы действий. Они не гарантируют ответы на любой будущий вопрос и не являются обещанием скорости на любом оборудовании.

При изменении модели, промпта, схемы или каталога сверяются артефакты Java, Docker и Python-стенда. Метаданные успешной генерации сохраняют использованные версии; случайная подмена весов по тегу отклоняется проверкой digest.
